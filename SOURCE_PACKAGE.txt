Change and compatibility
------------------------
Kickstart verifies and normally loads the optional restricted WC module.
The helper uses Device control/packet memory at 0x3fc00000 for 1 MiB, and a
separate WC-or-Device pixel window at 0x3fd00000 for 3 MiB. Singleton ownership
precedes all mappings. Control and pixel mappings never overlap; existing
publication barriers, session checks, banking and rendering remain unchanged.

An absent or kernel-rejected optional module falls back to Device pixel
publication. A partial/corrupt module+checksum pair is rejected by Kickstart;
re-extract the full package. No forced module insertion, kernel replacement,
permanent boot service or clock changes are included. Normal load, aperture
checks and unload passed on the test MiSTer. Matching vermagic alone is not
proof of compatibility with every other kernel build.

The module was built using modules_prepare without Module.symvers and with
CONFIG_MODVERSIONS disabled. Six unresolved modpost import warnings were
checked against live symbols and the pinned source's EXPORT_SYMBOL entries;
normal hardware insertion then succeeded. The exact prepared config differs
from the captured live config only by an added disabled CONFIG_HID_VADER4 entry.
The pinned kernel is the module build dependency, not a claim about the source
commit used to build the running test kernel. See module build provenance.

Measurements and validation
---------------------------
Device/WC/Device production pixel-publication comparison at stock 1 GHz:
all changed pixels averaged 9.294 / 1.823 / 9.286 ms (80.4% less time);
one in sixteen blocks changed averaged 1.724 / 1.172 / 1.667 ms (29.7–32.0%).
All 336 readbacks matched; 8 warmups + 48 measurements per workload per run.
This includes comparisons/packing/stores/barriers and the existing WC NEON
writer; it excludes real FPGA ACK waiting and is not a game-FPS measurement.
Sparse WC maximum latency exceeded one Device repeat despite better mean/p95.
No universal hitch reduction or measured whole-game speed percentage is claimed.

Normal NSMB checks reached animated menus, its opening movie and World 1 map.
The maintainer reported a large perceived WC speed gain with an experimental
arbitration core, then requested the accepted FPGA with WC and this package.
That user comparison does not isolate WC-only FPS. This package excludes the
experimental FPGA. Final-pair gameplay/audio and reset/ROM-switch qualification
is limited. Strange Journey's intro freeze persists in both memory modes.

Source-identical host and ARM-emulated tests passed: ABI, mapping alias/bounds,
fallback/cleanup, singleton and lifecycle, launcher/hash handling, 24 service
Engine B/publisher/replay combinations and full-frame display capture. Packaging
checks the matching source, manifests, exact binary identities, complete source
archive, ZIP CRC/contents/modes, and the public-source/history audit. Hardware
results and bounded tests do not establish universal game compatibility.

FPGA resources and timing are unchanged from beta.2: 41235 ALMs needed,
41101 placed, 4191/4191 LABs, 510/553 M10K, 69/112 DSP.
Worst setup -13.670 ns, hold -0.021 ns, recovery -10.889 ns, removal +0.406 ns.
Timing is not closed. The prior RESET5 report has 83 timing rows regressing
versus beta.1. This release introduces no new FPGA routing or area change.

Retained behavior and limitations
---------------------------------
Engine B defaults Off and changes on Reset/ROM reload. Off copies Engine A to
both screen positions; On restores Engine B at a performance cost. CW/CCW TATE,
rotated controls, stability/ROM-switch fixes, smoother movies and audio,
Chrono/Kirby/palette fixes, touchscreen and cartridge saves remain.
Movies/audio can still hitch and games may run slowly, glitch or crash.
Pokemon's slow GX readback correction remains excluded (GitHub issue #16).
No credits menu was added. Networking, microphone, NAND saves and save states
remain unimplemented. Wi-Fi register compatibility does not provide networking.
