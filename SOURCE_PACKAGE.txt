NDS4MiSTer v0.3.0-beta.11 source — fast single-screen release

This source snapshot accompanies NDS4MiSTer_Public_Beta_v0.3.0-beta.11_20260910.
It freezes the latest accepted ARM speed improvements and independent FPGA
fixes from the single-screen beta.10 development lane. Beta.12 is planned for
Engine B with an On/Off option, default Off and applied on Reset or ROM load.

Production source baseline: dc0c9da (accepted palette parent 30e1608).
The packaging documentation is updated in this snapshot; the production code
and build assignments are unchanged from that baseline.

Included changes
----------------
- Latest accepted ARM renderer work, including constant-color span/depth reuse,
  exact translucent shading work, responsive adaptive catch-up, and the replay
  worker missed-wakeup correction. Public beta.10's parallel shadow/stencil
  work, specialized antialias final pass, and frontend CPU0 pinning remain.
- Kirby graphics fixes: extended-palette refill after VRAM remaps, local ARM9
  VRAM write retirement, and disabled-Engine-B register readback.
- Standard-palette readback for fade/text-color behavior.
- Independent ARM9 halt/IRQ-resume correction: preserve the pending decoded PC
  when IRQ selection occurs on the edge that clears halt.
- Existing sound-bias correction, touch calibration and pointer, EEPROM/FRAM/
  Flash saves, and InsaneFriend's writable firmware, ARM7 Wi-Fi boot-memory,
  and cartridge-IR compatibility work. Wi-Fi register compatibility does not
  provide networking.

Deferred work and limits
-----------------------
Engine B rendering is excluded. Both screen positions display Engine A.
The experimental GX readback path is excluded because its FPGA/ARM pairing
caused substantial slowdown. It supplies the clip-matrix and BOX_TEST results
needed by missing Pokemon player/furniture graphics, so those objects can
remain missing in this fast build. See GitHub issue #16:
https://github.com/SplashDev88/NDS4MiSTer/issues/16

Up to about 30% faster 3D rendering in targeted tests: the latest translucent
optimization reduced a complete synthetic frame from 126.246046 ms to
97.746822 ms on MiSTer at 1 GHz (29.16% higher throughput), against its preceding
accepted build. Results vary by game. This is not a whole-game FPS comparison
against public beta.10.

No claim is made that all games run at full speed or that all graphics, save,
audio, or crash problems are solved. FPS/publication counters do not measure
unique displayed frames or total gameplay speed; see issue #11.

Validation
----------
The production nds_cpu9 WFI/BX caller-return test passes 130 cases across five
memory latencies, thirteen wake phases, and IRQ enabled/masked operation.
The baseline negative control fails by skipping the post-WFI return instruction.
The standard-palette readback regression and source safety audit pass.
The seed-2 FPGA completed map, fit, assembly, and timing analysis. The
maintainer confirmed good graphics/gameplay and retained fast responsiveness
in Castlevania: Dawn of Sorrow and New Super Mario Bros. on this exact pair.
The Castlevania hardware smoke check also reported Ready and no FPGA/HPS faults.
Fit: 40,850 ALMs, 491 RAM blocks, 69 DSP blocks. Static timing reports setup,
recovery, and hold violations; timing closure is not claimed.
Static timing is retained as diagnostic information. Simulation and source
checks do not establish game speed or universal stability.

Source contents and licensing
-----------------------------
Contains the tracked FPGA/ARM sources, build and test scripts, generated-image
source for the free boot code, and component license/attribution files.
Commercial ROMs, console BIOS/firmware dumps, personal saves, credentials,
private handoffs/captures, developer paths, and compiled build databases or
binaries are excluded. Installable binaries are supplied separately.
