NDS4MiSTer v0.3.0-beta.14 source — smoother FMV playback and TATE mode

This snapshot accompanies NDS4MiSTer_Public_Beta_v0.3.0-beta.14_20260914.
Movie playback is smoother, with occasional audio hitches still possible.
Video Rotation adds Off / 90 CCW for a physically rotated monitor. Engine B
and rotation default Off. Engine B changes apply after Reset or ROM reload;
rotation changes do not require a reset.

Only documentation and SHA256SUMS change after this production commit. All
476 frozen FPGA input hashes match TATE10, and ARM sources/build configuration

Included changes
----------------
- Earlier ARM9 instruction/data returns, eligible load retirement, load-base
  reuse, and cached-write completion at RAM commit. Preserve collision,
  reset, maintenance, and request-ownership guards.
- Joined compatible adjacent LCDC reads, and sound refill access between
  complete ARM7 DMA transfer units with repeat/resume behavior preserved.
- Engine B unchanged-line reuse and completed-snapshot ownership transfer
  without an additional full-image copy in the matched ARM helper.
- Accepted VRAM victim-storage optimization and equivalent sound-register
  readback. Passive sound/display diagnostic payloads are omitted to fit.
  Sound fetch/decode/mix/scheduling, fault/session control, PC heartbeat,
  ARM runtime telemetry, and the on-screen FPS counter remain.
- Four-row RGB666 TATE capture through the scaler DDR port, triple frame
  ownership, complete-frame publication, and native controls.
- Prior CPU/cache and ARM/3D speed work, optional Engine B, Chrono startup,
  sprite and movie fixes, Kirby and palette graphics, transparency, processor
  wake-up, touchscreen, sound, cartridge saves, and boot compatibility.

TATE and performance scope
--------------------------
The picture rotates 90 degrees counterclockwise. Turn the monitor clockwise,
select Top/Bottom, and set Video Rotation -> 90 CCW. Controls retain native
DS directions. Screen order/gap remain available. MiSTer menu rotation is
separate; see README.md. Only CCW is exposed, leaving the wider rotation
feature request partly open.

TATE replaces normal scaler capture while On. Steady Off operation adds no
rotation requests or extra request-cycle latency. Shared DDR contention and
physical placement can still affect performance; zero On cost is not claimed.
If capture misses its deadline, the previous complete frame stays displayed.

Engine B On restores the second graphics engine using the ARM helper, but
costs speed and can lag under load. Off copies Engine A to both screen positions.
No whole-game speed percentage or universal full-speed playback claim is made.
Audio remains experimental, and occasional movie hitches can remain.
The slow experimental GX readback correction remains excluded; see:
https://github.com/SplashDev88/NDS4MiSTer/issues/16
No credits menu or ARM overclock was added. Networking, microphone, NAND saves,
and save states are not implemented. Wi-Fi register compatibility is not Wi-Fi.

Validation
----------
The maintainer reported markedly better playback on the retained WCR1 movie
path, then requested TATE and release packaging. TATE10 was loaded for manual
testing without a ROM autoload. This is limited maintainer feedback, not a full
TATE10 game, display, or input compatibility matrix.

Focused tests cover CPU/cache/write returns and collisions, LCDC backpressure,
sound refill/repeated DMA ownership, Engine B line/snapshot ownership, VRAM
storage equivalence, TATE native canvases and all 262,144 RGB666 colors,
Avalon stalls, late-frame recovery, and Off pass-through. Sound readback passed
888,352 checks, full sound-unit comparisons, and three negative controls.
The final control/heartbeat comparison passed 5,034 paired cycles plus a
heartbeat-corruption negative control and Engine B session tests. Unchanged
results were retained only after source-hash comparison. Portable RAM and
finite scaler tests have modeling/initialization limits and do not prove
universal hardware correctness or speed.

GPL reference fixtures allow sound/VRAM equivalence tests to run from source
archives without development Git history. Both archive-ready runners passed
during packaging, including sound negative controls. Source/archive hashes,
installer contents, executable bits, and exact binary identities are checked.

Map, fit, assembly, and timing analysis completed. Resources: 41,238 ALMs
needed; 41,022 placed; 4,191/4,191 LABs; 510/553 M10K; 69/112 DSP.
Worst setup -13.873 ns; hold -0.366 ns; recovery -10.925 ns; removal +0.263 ns.
Timing is not closed. Unused ALMs do not establish freely placeable headroom
when every LAB is occupied. Broader hardware regression remains. Omitted
passive diagnostic words are not evidence of zero sound/display stalls.
