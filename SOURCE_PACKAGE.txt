The exact user-tested helper and existing v0.5.1 FPGA/launcher/module are
packaged without rebuilding. Only source documentation and manifests change
after the compiled ARM revision. The same core filename is intentional:
this helper-only fix does not install a second dated FPGA core.

Changes since v0.5.1:
- Reclaim retired matrix-prefix queue entries before checking its storage
  bound. Retired work must not permanently disable fast replies.
- Give simple state/attribute commands conservative 16-cycle eligibility
  costs instead of 128. Preserve the existing total work and live-word caps
  and the unchanged matrix/vertex/SWAP/BOX costs. This affects eligibility,
  not guest timing or renderer arithmetic.
- Send geometry/test-busy queries through the existing ordered reply owner.
  Settled queries retain immediate replies. FFT startup otherwise reused
  the previous projection and drew clipped grey rectangles. Per-fence
  matrix verification alone did not catch that timing interaction.

The user accepted restored FFT menu speed, confirmed NSMB and Castlevania
speed held up on the performance parent, then confirmed the final startup
fix "works great". Both startup logos match the full-CPU melonDS reference
geometry in hardware captures, with zero fault words. A 25-second FFT menu
window measured 59.77 source frames/s and 29.87 paired publications/s versus
59.85 and 29.93 on the accepted performance parent: effectively unchanged.
These transport/source rates are not unique animation FPS. No universal
60-FPS claim, full-playthrough claim or measured all-game speedup is made.
