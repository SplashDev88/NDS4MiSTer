Scope and validation
--------------------
Cartridge transactions retain physical ownership across guest resets and
suppress old replies. Video session validity discards old frames/line slots
without clearing large RAM arrays or abandoning accepted DDR transactions.
Rotated short OSD messages address their active64-pixel height rather than
old file-list rows. Engine-B display capture uses the complete-frame 3D fence
when the fast renderer omits scanline tokens; later fences reuse completion.
Renderer startup/reset jobs re-arm that completion state.

The maintainer tested the pair on MiSTer and reported that it worked great,
then requested packaging. Prior failure evidence involved Strange Journey
followed by other ROMs staying black. No detailed compatibility or speed
matrix was reported; no measured speed gain or universal game support claim.

Reset/cart/video finite simulations and negative controls passed during
candidate development. The OSD regression checks301056 pixels across both
rotated directions and Off; baseline fails20480 checks. Threaded capture
checks8 modes with4 frames each, compared with an explicit completed-frame
oracle, including repeated fences and renderer restart. Host and ARM-emulated
capture/service/lifecycle tests passed; capture also passed on physical MiSTer.
The unchanged baseline renderer hangs in the new early-capture negative test.
Earlier test results are retained only for source-identical implementations.
Simulation and finite oracles do not prove universal hardware behavior.

All478 frozen FPGA source/test inventory files match RESET5. ARM source and
build configuration match CAPTURE1. Source/archive checksums, install archive
CRC, contents, file modes and exact binary identities are verified separately.
FPGA fit:41235 ALMs needed,41101 placed,4191/4191 LABs,510/553 M10K,69/112 DSP.
Worst setup-13.670ns, hold-0.021ns, recovery-10.889ns, removal+0.406ns.
Timing is not closed.83 timing rows regress versus beta.1 despite improved
aggregate worst slack. Playability feedback is the maintainer's acceptance
criterion; compilation and area figures are not a gameplay speed measurement.

Retained behavior and limitations
---------------------------------
Engine B defaults Off, with changes applied on Reset or ROM reload. Off copies
Engine A to both screen positions. On restores the second engine at a speed
cost. CW/CCW TATE, native input rotation, earlier movie/audio and ARM speed
work, Chrono/Kirby/palette fixes, touchscreen and cartridge saves remain.
Movies/audio can still hitch; demanding games can fail or run slowly.
The slow experimental Pokemon GX readback correction remains excluded:
https://github.com/SplashDev88/NDS4MiSTer/issues/16
No credits menu was added. Networking, microphone, NAND saves and save states
remain unimplemented. Wi-Fi register compatibility does not provide networking.
