# Side-by-side DV1 menu width (private beta, 2026-10-25)

The user accepted the previous stacked-menu build as the next release baseline, then requested that the horizontal Side-by-side menu be closer to the width of Main-only. This follow-up starts from the exact accepted package, SHA-256 `49a859e8871efce27041f8e3a4ac73d26383a53d0c41a5aac8f63f5bab2a7599`, source `62b4665bd187e21d1dfcf640aeecdfe1a9e27955` (local tag `baseline/rc10-dv1-20261025`). The accepted package and installed baseline kit are retained.

Implementation: `78a0f17d2657013d739af9184d2dbbf428cd88e2`. Only `sys/osd.v` and `sys/sys_top.v` differ from the accepted frozen FPGA inputs. The host remains `d6e789772cc238e626b2b6dedaea1159142ffa02a8cfe3f231a9fa2f82dcd6c6`, built from `ee6ac636cdba4dfc1b1492d5766cd3eff2354b22`; the renderer remains `bb13597d032d9d365b9763efa3866594c8562e5476b4c02b93ba55754f9f7570`. No changes to gameplay, FMV caching, stock loading dialog, RTC or Right Stick Range are introduced here.

The new gate requires native DV1 with metadata, no applied native game rotation, source width above 320 and source height at most 240. This selects the unrotated side-by-side layouts, including screen gaps and the optional FPS row. It is mutually exclusive with the existing stacked-menu gate. The menu uses half the original integer horizontal sampling period, rounded down with a minimum of one clock. Actual side-by-side transport uses six clocks per old menu column, reduced to three. There is no additional bitmap, framebuffer, divider, HPS operation or video pipeline stage. Menu height and the game RGB/sync pipeline are retained.

At the user's unchanged RetroTINK profile, the accepted reference captures measured Side-by-side at 854 by 428 pixels and Main-only at 409 by 342. The expected width correction is about 427 pixels, not a promise of identical physical dimensions on all receiver profiles. It retains even integer-spaced columns. Height remains unchanged as requested by the width-only scope. Auto Fill Int already crops the outer game edges in side-by-side; this change does not modify that profile or game geometry.

Validation before build: 4,538,368 output/layout/rotation gate combinations passed across normal, NO_TATE, MISTER_HDMI_ONLY and NDS_HDMI_SCALER_ONLY builds. The updated independent reference raster passed 33,501,576 RGB/sync samples across 25 cases, including eight- and sixteen-row side menus, hidden-menu passthrough, minimum and odd sampling periods, accepted stacked behavior, Main and rotated modes, explicit legacy OSD rotation, and simultaneous independent analog output. The independent width specification uses integer division against the original pre-native-pixel OSD raster. Reproduce with `tools/test_dv1_dual_menu_gate.py` and `tools/test_dv1_legacy_width.py` using the existing Verilator Docker image.

The unchanged RetroTINK NDS 1080p profile uses firmware 1.99.5, LCD Mono 2, Auto Fill Int and 1:1 square pixels. Opening the core menu still changes the horizontal input sampling via the legacy high-resolution OSD metadata. The initial inference that this also changed the LCD grid was incorrect. Full-resolution 1920x1080 captures demonstrated that LCD Mono 2 retains the game grid's spacing and phase: Side-by-side 5 pixels, Main 4 pixels, Top/Bottom 2 pixels and Top/Bottom CCW 4 pixels, with the menu open and closed. On the Side and Main samples, all detected dark grid columns matched; the Top/Bottom background strip matched exactly. The retained fine stock menu font has its own pixel spacing, distinct from DS pixels. No font or metadata change was needed to preserve the game grid.

The initial screenshots used 720p60 capture, which resamples the 1080p output. Capture was temporarily changed to the device's supported 1080p30 mode for static grid inspection, then restored byte-for-byte to its previous settings. The RetroTINK profile was not changed. A metadata-only diagnostic that suppressed the high-resolution flag was isolated, evaluated and rejected; its host is not included in this package. The earlier font-choice question was withdrawn after the full-resolution result corrected the premise.

The completed bitstream is `4923bf975da940ac91240f9b4a08e0d3762253363b084bc99893ea2211160482`. Map, fit, assembly and timing-analysis commands returned zero. The fit uses 34,675 ALMs, 538/553 RAM blocks and 27 DSP blocks. Static timing still fails: setup -15.205 ns, hold -0.432 ns, recovery -14.020 ns. The accepted build had +0.066 ns hold slack. This new hold violation is an additional reason to retain the accepted release baseline and treat this as a private visual test candidate.

Live 1280x720 capture bounds were Side-by-side 426x428 (previously 854x428), Main 409x342 unchanged, Top/Bottom 228x342 unchanged and Top/Bottom CCW 455x342 unchanged. Menus remained centered and DV1 geometry packets matched their accepted references exactly. A static Main menu crop matched RGB-for-RGB. The side width is about 4% greater than Main in this profile; height is intentionally unchanged. NSMB booted using an isolated copy of its save and reached the World 3 map. Layout switching and menu open/close passed, followed by a clean exit with zero save writes. All 27 protected files and 1,121 original save records remained unchanged. No gameplay speed claim is made.

Reproduction evidence is in `evidence/dv1-side-menu-width-20261025`: BUILD_REPORT.json, HARDWARE_REPORT.json, COMPARE_*.json, LCD_1080_* captures/alignment checks, PRESERVATION_FINAL.json, and the package/install validation receipts. The accepted tag and baseline pointers were not moved.

Limits: legacy menu stays upright in the core. Physical dimensions depend on receiver scaling. FPGA static timing closure remains unresolved. No fresh whole-game FPS benchmark or input-to-photon latency measurement is implied by the unchanged pipeline. HDMI and independent analog isolation are covered in simulation; any physical output checks are stated above. This is a bounded private-beta menu change, not broad release qualification.
