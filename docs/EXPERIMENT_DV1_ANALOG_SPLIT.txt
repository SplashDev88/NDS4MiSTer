NDS4MiSTer: independent digital layouts and single-screen native analog
2026-10-12 — private implementation; hardware acceptance pending

Branch: experiment/dv1-analog-split
Base: v0.9.0-rc.7 / dc020c6fb9ba794a98f4a92a2f9c2fd48919f9d5

Scope and controls
==================
Analog CRT always receives ONE unscaled 256x192 DS screen centered at (32,24)
in 320x240, with fixed 262-line native timing. Never shrink a paired layout
onto the CRT. Digital Layout offers Main, Touch, Side-by-side and Top/bottom.
Digital transport can be native HDMI DV1 or the existing scaled HDMI path.
The intended private-kit starting selection is digital Main, analog Touch.

Independent Outputs defaults Off in the core. Status bit 14 enables it;
bit 15 independently selects analog Main/Touch. The framework permits the
mode with vga_scaler=0 and no Linux framebuffer override, on analog-capable
builds. Scaled VGA retains its existing behavior. The host queries command
0x46: existing signature/config words are unchanged, and new capability word
0x5350 identifies this ABI. Old cores cannot enable the experimental option.
Existing settings format and old menu action IDs are retained.

Screen Peek temporarily flips single-screen outputs while held; a paired
digital layout remains paired. Release restores the underlying selections.
Temporary Peek status is not saved. Physical screen order, gap controls,
touch pointer, 3D FPS, lid, microphone, audio and rendering profiles remain.
Native rotation follows rc.7: upright CRT and receiver rotation on DV1.
Existing scaled HDMI TATE/menu rotation remains available. Independent native
FPGA rotation would require another feature, not an implicit layout change.

Implementation
==============
There is one renderer frame-publication owner and adoption ACK in the original
scanout. The digital raster remains the original scanout output and scaler
input. A second small analog counter/pixel path uses the same video clock.
All split geometries have the same frame duration, 1,006,080 video clocks:

  Analog and digital single: 384 dots x 10 clocks x 262 lines
  Digital side-by-side:      640 dots x  6 clocks x 262 lines
  Digital top/bottom:        640 dots x  3 clocks x 524 lines

At nominal 60 MHz this is 59.6374 Hz. Analog always uses 15,625 Hz horizontal
sync and 240 active lines. Top/bottom digital has a separate 31,250 Hz raster;
it can never reach the analog pins in split mode. Digital paired layouts keep
both 256x192 images, existing gaps and order. RetroTINK acceptance of these
combined DV1 geometries remains a hardware test, not a simulation conclusion.

The existing 1024x36-bit line RAM is reused, with four contexts indexed by
{output,physical screen}, each having two whole-line slots. Digital reads use
video-clock phase 0; analog takes one free early clock in each ten-clock dot.
Each pixel path captures the synchronous RAM result before its pixel enable.
No new framebuffer, renderer or scaler is instantiated.

Four pending descriptors and one ticket per context arbitrate the existing
DDR reader. Completion tickets have an extra video-domain settling clock
after slot metadata synchronization. One job per context may be outstanding.
Each output acquires its
last completed slot only at a row boundary; it cannot request the next line
until this acquisition occurs. The writer always targets the other slot.
A delayed read holds a whole old line, rather than changing slots mid-row.
A shared frame epoch expires queued/issued work from before frame adoption;
issued DDR commands drain and return their ticket, but cannot promote stale
or recycled frame data. Session withdrawal drains both output contexts and
blanks stale pixels. Legacy parity-cache behavior is unchanged with split Off.

Digital requests use h=16 and h=64; analog prefetch uses its own h=96.
Those request clocks do not collide across the three digital pixel cadences.
A third panel read (paired digital plus one analog) costs about 35.18 MB/s
before bus overhead, versus 23.45 MB/s for two panels. Average bandwidth is
not evidence of meeting row deadlines; simulation exercises contention and
hardware measurements must check cadence/faults. Game clocks and NSMB's
existing alternate rendering-update profile are unchanged.

Framework routing gives analog its own scanline pipeline, native OSD timing
and csync. The same OSD commands feed a second 14-bit-counter OSD instance;
the bitmap consumes four additional M10Ks. This deliberate cost supports
independent raster geometry. DV1 continues through the existing digital OSD
and reconstruction/transmitter path. In split mode DV1 always carries RGB;
only analog follows RGB/YPbPr/composite/S-video conversion. Legacy YC-over-DV1
selection is unchanged when split is Off. Analog scanline inputs convert the
negative source sync polarity to the framework's positive convention.

Resource budget
===============
rc.7 fit: 40,611/41,910 ALMs, 549/553 M10Ks, 44 DSPs. Initial experimental
synthesis passed and retained the original 36,864-bit line RAM. The new menu
uses the remaining four M10Ks. Short new scanline/csync delay chains are
constrained to registers so tiny inferred shift RAMs do not waste blocks.
Actual placement/routing remains required; no functionality is trimmed.
Static timing reports are diagnostic only. Hardware behavior determines
acceptance, and timing violations alone do not withhold a build or test.

Validation and limits
=====================
Run tools/test_split_video.py for tagged Main/Touch pixels through the real
scanout and real DDR line cache. It tests all four digital layouts, both
analog selections, both screen orders, gaps, external-plane movement, touch,
late rows, a read stalled across a frame publication with its source recycled,
session withdrawal and switching split Off/On while DDR remains owned.
The two variants cover external_frame_mode Off and On; rc.7 uses the latter.
The bench supplies frame publications directly and is not a full HPS/renderer
protocol integration test. It checks immutable visible slots and exact fixed
analog timing. Existing reader/publication, legacy scanout, native OSD and
host display/Peek/lid/mic/rotation tests are also required.

Hardware work remains: build and install a separate private kit, capture each
assignment and all digital geometries, check menu/crop/lock/audio, measure
analog displacement and gameplay cadence, and inspect existing fault receipts.
Keep renderer identical to rc.7. Use an isolated NSMB ROM/save alias; preserve
original SD/NAS saves, normal install, maps, settings and MiSTer.ini.

The one-card rig can capture digital and analog sequentially through the
RetroTINK-4K. That cannot prove simultaneous display timing or physical CRT
acceptance. Test the real CRT alongside DV1 on the RetroTINK; a second capture
path is useful for measurement but not necessary to play.

Nothing from this experiment may be pushed or published without the user's
separate approval. No new hardware success is claimed by these RTL results.
